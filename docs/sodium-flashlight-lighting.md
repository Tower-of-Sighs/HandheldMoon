# Sodium 手电筒顶点光照

手电筒光现在单独接入 Sodium / Embeddium 的光照管线。普通环境光、天空光和 AO 继续由原管线计算；手电筒在管线完成后按实际顶点坐标采样光锥，再与环境光合并。

旧路径先把动态光写入方块采样，Sodium 又将其压缩成整数亮度、进行四点平均和暗样本补亮。窄光束近端只有少数采样格被照亮时，这会产生亮尖、色边；靠邻格支撑压暗会同时降低光束亮度。新路径让手持手电筒跳过这段整数采样，不再对它使用边缘压暗或暗侧补一级亮度。

## 处理顺序

1. `PlayerFlashlightLineLightBehavior` 通过 `usesVertexLighting()` 选择连续采样。引擎沿用已捕获的光源快照、空间索引和区块重建通知。
2. `SodiumLightDataAccessMixin` 包装 `LightDataAccess.compute` 中的光照采样。该线程的方块采样暂时排除这些手电筒光源；原始查询和过滤查询使用独立缓存。`finally` 恢复采样范围，且范围不会传播到其他网格线程。
3. `SodiumLightPipelineMixin` 在 `SmoothLightPipeline.calculate` 和 `FlatLightPipeline.calculate` 返回处采样每个顶点。相邻共面的面片使用同一世界坐标，保留小数光照，不把零亮度邻格替换为亮格。
4. 只提高顶点的方块光照分量；保留天空光、AO、模型自带亮度以及更亮的原有光照。光色只应用于新增的光照能量，保留原有环境光及其颜色。

光源关闭或移除后仍使用原有重建机制恢复网格。未选择顶点光照的光源、缺少解析快照的光源以及非 Sodium 渲染路径继续使用原来的处理。

## 版本适配

| 目标 | 接口与适配 |
| --- | --- |
| Fabric / NeoForge 26.1 | 共用 Sodium 0.8 管线 Mixin，直接更新可修改面片的颜色。 |
| NeoForge 1.21.1 | Sodium 0.6 的方块缓存接口相同；面片颜色、亮度与材质接口不同，因此使用 target 内的管线适配。 |
| Forge 1.20.1 | Embeddium 的 Sodium 0.5 接口，`calculate` 少一个参数，旧版不可修改面片的颜色通过 `QuadLightData` 传到写入顶点步骤。 |
| Fabric 1.20.1 | Sodium 0.5.13，使用旧版管线适配；其 `ModelQuadView` 不提供 Embeddium 的模型亮度读取方法。 |

旧版管线 Mixin 在各 target 的 `prepareCommonSources` 排除清单中登记。1.20.1 的附加 Mixin 与原来的兼容层共用插件，仅在 Sodium / Embeddium 存在时启用。

26.1、1.21.1 与 Fabric 1.20.1 的采样范围使用 MixinExtras `WrapMethod`，编译接口版本为 0.4.1，运行依赖由现有加载器提供。Sodium 0.5.13 的缓存直接读取世界亮度，Fabric Loader 0.16.14 提供 MixinExtras 0.4.1。Forge 1.20.1 的 Embeddium 缓存通过 `LevelRenderer.getLightColor` 取得动态光，因此在该调用处使用原生 Mixin `Redirect` 并通过 `finally` 恢复范围；这避免要求 Embeddium 0.3.31 内置的 MixinExtras 0.3.5 提供尚不存在的 `WrapMethod`。

## Forge 1.20.1 内圈额外渐变

2026-11-12：针对“外缘渐变正常，但全亮内圈又出现一段渐变”的反馈，修正 Forge 1.20.1 第一人称同时启用真实光照与屏幕后处理时的渐变错位。

原先后处理使用固定屏幕半径：在 70° FOV 下，约离轴线 24° 就开始减弱，34° 左右结束；真实手电筒却在约 28.6° 内保持完整角度系数，到 40.1° 才结束。两层效果叠加，会让全亮内圈提前丢失后处理增亮，再进入真正的光束外缘。

现在后处理通过该版本 `GameRenderer.getFov` 的 Mixin invoker 取得有效 FOV，将像素位置还原为视线夹角，使用与真实光照相同的内外半角及余弦衰减区间。第一人称真实光照开启时，后处理中心与实时光束方向对齐；仅启用后处理及第三人称仍使用原来的屏幕滤镜范围。真实光照的中心亮度、距离衰减和外缘角度没有调整。

验证在 Forge 47.3.0、Embeddium 0.3.31、Mixin 0.8.5 的实际客户端执行，开发期 Embeddium 副本已从 SRG 映射到官方名称；临时映射副本不进入发布包。除原有光照管线断言外，直接在 GPU 上编译并绘制最终 shader，读取离屏帧缓冲：45°、70°、100° FOV 下可见内圈保持同一输出值，外缘正常渐暗，光束外与未增亮基准一致。客户端正常退出。

运行验证同时发现 Mixin 0.8.5 无法复制顶点颜色数组字面量初始化中的 `IASTORE`；Forge target 已改为分配数组并在目标构造完成后填充白色，保留相同初始颜色。

此次 Forge 1.20.1 正式包已执行 `clean build`（包含 `reobfJar`），36 项测试通过；`common build` 的 36 项测试也通过。之前缺失的构建工具已补齐，以上 11 月 8 日的构建阻塞记录已解除。正式 JAR 位于 `build/sodium-flashlight/HandheldMoon-forge-1.20.1-1.3.0.jar`，已检查生产 refmap、shader uniform 与 metadata，并确认没有临时测试类。

## Forge 1.20.1 滑块拖动与后处理颜色

手电筒配置页面的滑块点击后不连续移动，是该版本 `AbstractContainerScreen.mouseDragged` 直接处理物品栏拖动、没有继续向已聚焦的滑块派发事件所致。页面现在把已开始的左键滑块拖动持续交给该滑块，松开时结束捕获，鼠标移出滑块边界也能继续调整并正常松开。配置仍在关闭页面时统一提交，不在每次鼠标移动时发包。

此前屏幕后处理只做无色 gamma 增亮，未读取灯具颜色或透镜强度。真实光照已经染蓝的情况下，后处理仍会抬高红绿分量，尤其容易在外围形成偏白增亮。现在 `BeamTint` 从同一 `Config.flashlightColorArgb` 取得颜色和强度，只给后处理新增的亮度染色，保留原有场景与环境光；颜色强度为零时仍为无色增亮。此次修正针对 Forge 1.20.1。

运行验证使用真实 Forge 1.20.1 + Embeddium 客户端：三个真实界面滑块在一次按住后完成 75 次连续拖动，拖出控件范围后仍可调整并正确松开。GPU shader 检查以 RGB `(51,51,51)` 灰底和满强度蓝色透镜测试，在离轴线 0°、26°、32°、36°、38° 分别得到 `(51,51,90)`、`(51,51,90)`、`(51,51,81)`、`(51,51,67)`、`(51,51,61)`；新增亮度仅进入蓝色分量，光束之外保持灰底。零染色强度恢复无色增亮，45°/70°/100° FOV 的平坦内圈检查和原有 Embeddium 光照管线断言继续通过，客户端正常退出。

## Forge 1.20.1 普通 runClient 的外围颜色

2026-11-16：普通 `gradlew runClient` 不会自动加载 `compileOnly` 的 Embeddium。用户最新启动日志也确认没有加载该模组，因此此前 Embeddium 管线和独立 shader 验证没有覆盖用户实际使用的原版方块路径及事件调用链。

原版 `DynamicLightBlockModelLighterMixin` 此前只按方块中心计算整面染色，但 AO 光照使用邻格得到每个顶点的亮度。光束边缘会出现方块中心没有有效蓝光、顶点却已被照亮的情况。现在根据可见面的采样平面和各顶点最终亮度分别计算颜色，将 ARGB 系数转换为原版烘焙顶点的 ABGR 格式，只复制需要染色的 quad，不修改共享模型顶点；保留原始 AO、天空光、biome 颜色、烘焙颜色与顶点光照。

事件入口还曾在非 `AFTER_PARTICLES` 阶段提前返回，导致只处理 `AFTER_LEVEL` 的 `EffectManager` 永远没有执行。现已将后处理事件分发移至该筛选之前，使其在完整世界渲染后执行。

本次在没有 Embeddium 的实际 Forge 客户端运行原版平滑与非平滑模型渲染器，验证 51 个旧中心采样返回无色、实际已被照亮的边缘顶点均保留蓝色，天空光不变。随后从正式 Forge 事件入口处理真实 PostChain 并读回主帧缓冲，得到灰底 `(51,51,51)` 到 `(51,51,90)` 的蓝色增亮。滑块连续拖动、45°/70°/100° FOV 内圈、蓝色外缘与零透镜强度检查仍通过，客户端正常退出。

本机需要测试 Embeddium 时，`targets/forge-1.20.1/runs/client/mods/embeddium-0.3.31+mc1.20.1-dev-named.jar` 是开发环境专用副本，字节码、Mixin 成员与 refmap 已映射到官方开发名称。直接在该 target 执行 `gradlew runClient` 会加载它；文件在 gitignore 的运行目录中，不进入掌中明月发布包，也不能复制到正常发行版实例。普通启动原本不会自动加载 `compileOnly` 的 Embeddium。

同日再次在 Embeddium 0.3.31 环境运行平滑／非平滑光照断言和正式后处理事件入口，全部通过。主帧缓冲同样得到 `(51,51,90)`，蓝色外缘、不同 FOV 内圈与滑块拖动回归检查通过，客户端正常退出。

Forge target 提供 `runVanilla` 客户端任务，游戏目录为 `runs/vanilla`，用于与 `runClient` 的 Embeddium 环境对比；两套运行目录的存档、配置与 mods 相互独立，掌中明月仍从当前源码加载。新任务已实际启动并验证没有 Embeddium，原版平滑／非平滑模型、正式后处理事件、滑块与蓝色外缘检查全部通过。

## 原版关闭平滑光照后的放置灯采样

2026-11-17：回滚地上灯连续顶点采样和像素光照尝试后，修正原版非平滑光照的独立问题。`ModelBlockRenderer.tesselateWithoutAO` 与 `renderModelFaceFlat` 向 `LevelRenderer.getLightColor` 传递的是正在绘制的方块状态和面外采样位置；两者可能属于不同方块。动态光注入此前用传入的石头状态判断是否为实心，导致面外空气处的采样也被跳过。现在使用 `level.getBlockState(pos)` 判断实际采样位置的状态，保留实心采样排除和原有方块亮度处理，不恢复已回滚的地上灯连续采样或像素着色器。

复现使用没有 Embeddium 的实际 Forge 1.20.1 客户端、放置灯的 `FullMoonEntityLightBehavior` 与受控石头平面，直接运行原版平滑和非平滑模型渲染路径。修正前非平滑受光顶点为 0，平滑为 542；此检查专门覆盖放置灯，不再用手持手电模拟光源代替。

修正后同一场景非平滑受光顶点为 484，平滑仍为 542，天空光保持原值，59 个方块中心无光但表面受光的位置保留蓝色。正式后处理事件、三个滑块拖动以及 FOV／蓝色外围回归检查通过，客户端正常退出。运行检查使用受控世界和实际放置灯行为、原版模型渲染器，未修改用户存档。
