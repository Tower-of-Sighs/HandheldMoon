# 26.1 与 1.20.1 的差异

核对来源：

- 26.1：`common/build/moddev/artifacts/minecraft-patched-26.1.0.19-beta-sources.jar`
- 1.20.1（Forge）：`targets/forge-1.20.1/build/moddev/artifacts/` 由 ModDevGradle legacyforge 生成的 official 命名 jar
- 1.20.1（Fabric）：Loom 生成的 1.20.1 官方映射 jar

两个 1.20.1 target（`forge-1.20.1`、`fabric-1.20.1`）共用同一份 Minecraft API，
因此它们排除的 common 文件完全一致；差别只在加载器边界。

## 由 SPI 吸收的差异

| 主题 | 26.1 | 1.20.1 | 处理方式 |
| --- | --- | --- | --- |
| 物品上的自定义数据 | `DataComponentType` | 无数据组件，物品只有 NBT | 新增 `spi/ItemDataPort` + `item/ItemData` 门面；26.1 target 用组件实现，1.20.1 target 用 NBT 实现 |
| 自定义数据组件注册 | `RegistryService.registerDataComponent` | 无此概念 | 1.20.1 target 自带 `spi/RegistryService`（去掉该方法） |

因为物品数据改走 `ItemData`，`util/Utils`、`util/ItemState`、`item/ColorLensData`、
`menu/FlashlightConfigMenu`、`client/screen/DeviceConfigTargets` 仍留在 `common`，
1.20.1 不需要为它们各写一份。

## 已确认差异（1.20.1 `prepareCommonSources` 排除的文件）

| 主题 | 26.1 | 1.20.1 | 影响的 common 文件 |
| --- | --- | --- | --- |
| 网络包 | `CustomPacketPayload` + `StreamCodec` | `FriendlyByteBuf` 手写编解码 | `network/Server*Packet.java`（8 个） |
| 方块 codec | `Block#codec()` / `simpleCodec` | 无该抽象方法 | `block/FullMoonBlock.java`、`block/MoonlightLampBlock.java` |
| 方块实体持久化 | `ValueInput`/`ValueOutput` + `HolderLookup.Provider` | `CompoundTag` | `block/FullMoonBlockEntity.java`、`block/MoonlightLampBlockEntity.java` |
| 物品 tooltip | `appendHoverText(ItemStack, TooltipContext, TooltipDisplay, Consumer, TooltipFlag)` | `appendHoverText(ItemStack, Level, List, TooltipFlag)` | `item/*.java` |
| 实体同步数据 | `SynchedEntityData.Builder` | `defineSynchedData()` + `entityData.define` | `entity/FullMoonEntity.java` |
| 渲染 | `SubmitNodeCollector` / `RenderPipelines` / `rendertype` | `PoseStack` + `MultiBufferSource` + `RenderType` | `client/renderer/*`、`client/LightSourceHighlightRenderer.java`、`api/raycone/impl/RayConeRendererImpl.java` |
| 后处理 | JSON 后处理管线（`post_effect`、`render_pipeline`） | 旧 `shaders/post/*.json` + `shaders/program/*` | `event/handler/EffectManager.java`、`event/handler/ShaderEventHandler.java`、`mixin/client/*` |
| 光照坐标工具 | `LightCoordsUtil` | `LightTexture` | `mixin/dynamiclight/*`、`mixin/client/EntityRendererMixin.java` |
| 条件物品模型 | `ConditionalItemModelProperties` | `ItemProperties` 谓词 + `overrides` | `client/renderer/item/MoonlightLampPoweredProperty.java` |
| 界面 | `GuiGraphicsExtractor` 等 | `GuiGraphics` + `Screen#render` 旧签名 | `client/screen/*` |
| 射线裁剪 | `ClipContext(..., CollisionContext)` | `ClipContext(..., @Nullable Entity)` | `api/raycone/RayConeGeometry.java`、`util/LineLightMath.java` |
| 资源标识符 | `net.minecraft.resources.Identifier` | `ResourceLocation` | `registry/ModKeyBindings.java`、`util/IrisCompat.java` |
| Java 21 `Math.clamp` | 可用 | 目标是 Java 17 | 无（common 已改成 `Math.min/max`） |
| Sodium 兼容 Mixin | 0.6/0.8 API（`net.caffeinemc`） | 0.5 API（`me.jellysquid`，Embeddium 0.3.x 同源） | `mixin/dynamiclight/Sodium*` 换成 1.20.1 的 `mixin/embeddium/SodiumBlockRendererMixin`（注入 `BlockRenderer#writeGeometry` 的顶点色数组） |

`dynamiclight/DynamicLightEntityRendererMixin` 在 1.20.1 同样适用，保留在 common。

### Embeddium / Sodium 0.5

Embeddium 0.3.x 与 Sodium 0.5.x 不用 `ModelBlockRenderer`，方块光走它们自己的
`BlockRenderer`。它们的亮度仍然经过 `LevelRenderer#getLightColor`（被
`DynamicLightBrightnessGetterMixin` 改写），所以动态光会亮，但不会带上光色；
`SodiumBlockRendererMixin` 在 `writeGeometry` 写顶点前把每顶点颜色乘上
`DynamicLightRenderHelper.tintCoefficientForVertex` 的结果补上这一环。

这个 mixin 引用 Sodium 的类，因此单独放在 `handheldmoon.embeddium.mixins.json`
（Fabric 为 `handheldmoon.sodium.mixins.json`），由各自加载器的 mixin 配置插件
在未安装 Embeddium/Sodium 时跳过，避免类缺失导致启动失败。只覆盖 Sodium 0.5 一代，
旧的 Rubidium 等 0.4 分支不会应用。

## 1.20.1 target 自带实现的文件

两个 1.20.1 target 都有一份与 common 同 FQN 的实现：

`api/raycone/{RayConeGeometry,RayConeRendererImpl}`、`block/*`、`client/LightSourceHighlightRenderer`、
`client/renderer/{FullMoonRenderer,MoonlightLampRenderer}`、`client/screen/*`、
`dynamiclight/DynamicLightEntityTint`、`entity/FullMoonEntity`、`event/handler/{EffectManager,ShaderEventHandler}`、
`item/*`、`mixin/client/*`、`mixin/dynamiclight/*`、`network/Server*Packet`、`registry/{ModDataComponent,ModKeyBindings,ModRegistries}`、
`spi/{AbstractClientPlatformService,RegistryService}`、`util/{IrisCompat,LineLightMath}`。

加载器专属代码（入口、注册表实现、网络传输、按键/界面注册、Curios/Trinkets/TACZ 兼容）
分别位于 `cc/sighs/handheldmoon/forge/` 与 `cc/sighs/handheldmoon/fabric/`。

## 资源差异

- 配方目录为 `data/handheldmoon/recipes/`（1.21.2+ 才是 `recipe/`），镜头颜色用
  `result.nbt` 而不是 `result.components`。
- 物品定义 `assets/handheldmoon/items/*.json` 是 1.21.2+ 才有；1.20.1 用
  `models/item/*.json` 的 `overrides` + `ItemProperties` 谓词。
- 后处理使用 `assets/handheldmoon/shaders/post|program/` 旧格式。
  1.20.1 的 `PostChain` 只接受**不带命名空间**的 pass 名（`"name": "flashlight"`），
  并把 `shaders/program/<name>.json` 解析到 `assets/minecraft/` 下，因此手电筒
  program（`flashlight.json` / `flashlight.fsh`）直接放在 `assets/minecraft/shaders/program/`。
- Curios 标签目录是 `data/curios/tags/items/`，Trinkets 是 `data/trinkets/tags/items/`。

## 构建差异

- `forge-1.20.1` 使用 `net.neoforged.moddev.legacyforge` + Gradle 8.14.4 + JDK 17，
  构建脚本同样是 `build.gradle.kts`；插件自带 `reobfJar`、run 的 mixin 配置/refmap 重映射。
  它的 dev 运行期不反混淆 mod 依赖，因此 Curios/TACZ 在构建里是 `compileOnly`
  （只用于编译兼容代码），AutoJS 测试则把 official 映射后的 jar 放进 `runs/client/mods`。
- `fabric-1.20.1` 使用 `fabric-loom`（1.20.1 仍需混淆 + 官方映射；26.1 用的
  `net.fabricmc.fabric-loom` 新插件只适用于已去混淆的版本）。
- Fabric 1.20.1 的 fabric-loader 0.16 不把 Mixin 暴露到编译类路径，需显式
  `compileOnly` sponge-mixin；Trinkets 3.7.2 的 API 继承 CCA 的 `ComponentV3`，
  而 CCA 只以嵌套 jar 形式存在，构建时抽出 `cardinal-components-base` 供编译。
